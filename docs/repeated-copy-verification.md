# 重复复制计数修复（桌面 0.1.4）

原实现每秒比较内容哈希，连续复制相同内容被视为没有变化；应用内「复制」还主动跳过累计。因此「常用的心头好」无法反映这些使用。

现在 Windows 使用 `GetClipboardSequenceNumber`、macOS 使用 `NSPasteboard.changeCount` 判断系统写入，每 250 毫秒检查一次。变更标识只比较是否相同，不把其差值当作复制次数。文字和图片都复用原记录并累计；应用内成功复制只增加所选记录一次，更新最后复制时间、持久化并进入现有同步队列。异步读写串行执行，读取中发生变更会重读；启动旧内容、空内容及被敏感标记过滤的内容不会增加次数。

次数表示观察到的系统写入、手动收录和应用内复制。两个检查之间已被覆盖的复制、源应用没有重新写入剪贴板的动作无法还原；历史漏计次数也无法恢复。原生接口不可用时保留内容比较作为降级方案。

## 验证

- `node --test tests/*.test.mjs`：24 项通过，含新增的 9 项计数回归及原有账号、真实 HTTP / SQLite、同步测试。
- Windows 真实 Electron 44.9.1 系统剪贴板：相同文字写入 5 次，加应用内复制 3 次，最终累计 8；相同 PNG 写入 3 次，累计 3；空闲检查不重复计数；原剪贴板恢复成功。
- 对本机生成的 Windows `app.asar` 内正式模块执行同一套真实剪贴板测试，结果一致，确认原生依赖已打包。
- CI 在 Windows 和 macOS 上执行真实剪贴板回归、构建安装包，并再次测试打包内模块；实际运行结果以对应 PR 的 Actions 为准。

```sh
# 设置 GARDEN_APP_ROOT 为安装包 resources/app.asar 的绝对路径后，
# 再执行同一命令即可测试包内正式模块。
```
