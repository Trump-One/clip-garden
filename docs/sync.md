# 同步协议 v1

客户端通过 Authorization: Bearer 会话认证。会话 token 在数据库中仅存 SHA-256 摘要，有效期 30 天，退出撤销。密码由独立随机 salt + scrypt 派生哈希保存。原生客户端在主进程发请求，API 不提供跨站 CORS，拒绝 Origin 请求头。

`POST /v1/sync` 输入 `{ cursor, operations }`。操作包含 `id`、唯一 `opId`、`baseRevision`、完整 `payload`。每批最多 50 条；客户端限制 20 条且总请求正文约 29 MB。服务端 SQLite 事务处理操作：

1. 用户 + opId 已成功执行则返回原 ACK，避免网络重试导致重复。
2. 当前版本不等于 baseRevision 则返回 conflict，不覆盖服务端数据。
3. 验证正文，修订 revision 并写入变更日志。
4. 返回用户自有、cursor 之后的最多 100 条变更，以及 hasMore / 新 cursor。

客户端持久化 outbox。提交未收到响应时重用 opId，确认后清理；请求进行期间的新修改使用新 opId，并在旧 ACK 后推进 baseRevision。服务器变更不会覆盖仍在 outbox 中的本机记录。并发冲突保留服务端记录和本机新 UUID 副本；本机删除与远程修改冲突时保留远程版本，需要用户再次决定删除。

删除以 tombstone 保留 UUID 和 revision，正文清空。变更日志中该 UUID 的既往正文也替换为当前版本，防止新设备下载已删除的历史正文。操作日志和 tombstone 目前不自动回收，适合首版小规模使用，长期部署需设计游标回收和全量重建。

桌面账号空间与游客空间分别保存，退出返回游客空间；账号缓存保留在本机，令牌清除。鸿蒙同样按账号分开保存，Asset Store 令牌与账号 ID 绑定校验。登录页面勾选合并时，把游客记录迁移为账号内新 UUID，提交本机持久化后再清空游客空间；不勾选就不上传。

前台鸿蒙 / 桌面运行时约 5 秒轮询。没有后台推送或实时 WebSocket；鸿蒙进入后台后系统可能暂停任务，返回应用再续传。服务端小规模单实例使用 SQLite WAL，不支持多节点同时写同一个数据库文件。
